# ONE dependency set for the whole deployment, duplicated on purpose.
#
# vercel.json declares two Python builds (demo/app.py and api/mcp_app.py) and
# @vercel/python gives them a single shared venv. Each build installs its own
# requirements file into it, and uv resolves that as a sync: whatever is not
# in the file it just read gets pruned. So the build that runs second decides
# what survives, and the first one is packaged against a venv missing its
# dependencies — which is how a deploy died on
#
#   ENOENT ... site-packages/babel-2.18.0.dist-info/METADATA
#
# (babel arrives via trafilatura -> courlan, and only the demo needed it).
#
# Both files therefore carry the union, and must be kept identical. Neither
# function needs every package; the venv they share does.
